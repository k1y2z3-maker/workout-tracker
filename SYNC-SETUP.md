# Workout Tracker V1.0 — file-scoped Google authorization
Static PWA; no personal training data, spreadsheet IDs or credentials are embedded in the source. Use a dedicated Google Cloud project. Enable Google Sheets API, Google Picker API and Google Drive API. Configure Google Auth Platform for External audience (personal Google accounts), Testing, with only your account as a test user. Configure drive.file scope only. Create a Web application OAuth client with authorized JavaScript origin https://k1y2z3-maker.github.io. Create a browser API key restricted to Google Picker API and HTTP referrers https://k1y2z3-maker.github.io/* and https://docs.google.com/* (Picker iframe). Enter OAuth Client ID, browser API key and numeric Cloud project number in app settings locally; never enter a client secret. Use Google authorization, then Google Picker to select the test spreadsheet first. The token is held only in memory; reauthorize after expiry. drive.file is per-file access for files opened/created/shared with this app, not a guarantee of exactly one file over its lifetime; use only the intended file and revoke grant if needed.
The app requires 歷史紀錄 A:X and 器械對照 A:C. Q/R array formulas are preserved. Writes cap at row 501. Deletion clears data fields but retains ID/tombstone. Optimistic read/compare/write is not atomic compare-and-swap; avoid simultaneous edits on multiple devices. New external rows without unique IDs are read-only until assigned IDs. Never sort partial columns. JSON exports include private local cache and queue; keep them private. No Google API responses are cached in service worker. Same-origin GitHub Pages apps share origin-level browser storage access, despite distinct localStorage keys. For stronger isolation use dedicated origin. Only test on a disposable copy. After successful tests export backup, clear pending changes, revoke grant and reset local binding; then select original spreadsheet. Do not use real data until validation is complete.
